- 2026-08-10 — STANDING RULE, repo-wide (per R42): every table created after migration `20260530000000_z2_admin_bypassrls` MUST create its own `admin_bypass` policy in its own migration, alongside `ENABLE`/`FORCE ROW LEVEL SECURITY`, its `tenant_isolation` policy and its GRANT to `payroll_app`. The reason is that z2 builds its list from `SELECT DISTINCT tablename FROM pg_policies` and therefore covers only tables that already had a policy WHEN IT RAN — it cannot reach back and cover a table created later. A new tenant-owned table that omits this gets FORCE RLS with no owner bypass, and `prismaAdmin` (which every background job and every cross-tenant admin path uses) then sees ZERO ROWS SILENTLY rather than erroring — the failure looks like "the feature does nothing" rather than "the feature is broken". Unit 0.13's `LeaveEntitlement` is the first table to follow this rule; it was caught only because its RLS was verified against a real PostgreSQL instance rather than assumed.
